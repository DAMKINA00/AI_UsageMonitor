# AI 사용량 모니터

이 PC에서 돌아가는 **Claude**(데스크톱 앱·Claude Code), **Codex**(데스크톱 앱·CLI), **Gemini**(Antigravity CLI `agy`), **Grok**(공식 Grok CLI)의
작업 상태와 남은 사용량을 한 화면에서 보여 주는 Windows 트레이 앱입니다.
캐릭터(클쨩·짚쨩·젬쨩·그쨩)는 기본으로 표시하며 상태와 한도에 따라 움직입니다. 세션 목록과 표시 옵션은 제거했습니다.

실행 파일: `publish\AIUsageMonitor.exe` (.NET 10 데스크톱 런타임 필요 — 이미 설치되어 있음)

## 보여 주는 것

| | Claude | Codex | Gemini | Grok |
|---|---|---|---|---|
| 앱 실행 여부 | `claude.exe` 프로세스 | Store판 `ChatGPT.exe`(OpenAI.Codex) / 직접 설치판 `Codex.exe` | `agy.exe` 프로세스 (조회용 제외) | `grok.exe` 프로세스 (조회용 제외) |
| 세션·스레드 상태 | `~/.claude/sessions/<pid>.json` + claude.ai 앱 대화·프로젝트 스레드 (작업 중 / 입력·승인 대기 / 완료) | `~/.codex/sessions/**/rollout-*.jsonl` 의 `task_started`/`task_complete` | `~/.gemini/antigravity-cli/conversation_summaries.db` (읽기 전용) | 개별 작업 상태는 수집하지 않음 |

| 기타 | 플랜(Max 5x/20x) | 플랜(Pro 5x/20x), 크레딧 잔액, 무료 리셋권 | 같은 결과의 Claude·GPT 그룹 쿼터는 도움말에 표시 | `subscription_tier` 등급·주간/월간 리셋 |

- 메인 화면은 **Claude / Codex / Gemini / Grok 네 행**입니다. 왼쪽은 계정 원, 오른쪽은 캐릭터와 말풍선입니다. Claude·Codex는 주 계정과 서브 계정 두 칸, Gemini·Grok은 주 계정만 표시합니다. 헤더에 요금제·앱 상태·조회 상태를 표시합니다.
- 계정 아이디는 **대문자·굵은 글씨**로 표시하고, 바로 아래에 한도 이름을 배치합니다. 남은 퍼센트는 원 가운데에, 리셋 타이머는 원 아래에 `5D 12H 24M` 형식으로 표시합니다.
- 계정별로 평소엔 **주간 한도**, 5시간 잔여량이 **10% 이하**이면 그 자리에 **5시간 한도**를 표시합니다. Fable 한도는 화면·트레이·사용량 알림·캐릭터 반응에서 제외합니다.
- 서브 계정 조회가 실패하면 마지막 수치를 흐리게 유지하고 계정명 옆에 경고 표시를 붙입니다. 도움말에서 마지막 확인 시각과 오류를 볼 수 있으며, 조회가 성공하면 정상 표시로 돌아옵니다.
- 리셋 시각만 지나고 새 값이 도착하지 않은 한도는 회색 원과 `확인 중`으로 표시합니다. 이때 100%로 초기화하거나 리셋 축하 연출을 하지 않습니다. 만료된 5시간 한도 대신 유효한 주간 한도가 있으면 주간 한도를 표시합니다.
- 원의 길이는 남은 비율이며, 색은 잔여량에 따라 녹색에서 노란색, 빨간색으로 부드럽게 변합니다. 원에 마우스를 올리면 플랜·리셋 시간·데이터 기준 시각·연결 상태를 확인할 수 있습니다. "한도 도달"·"한도 도달(추정)" 같은 사용량 경고가 있으면 원 위에 ⚠ 를 붙이고 도움말에 문구를 보여 줍니다.
- Codex 스레드 상태는 실제 작업 이벤트 시각으로 판단합니다. Codex 앱이 켜질 때 모든 스레드 로그에 덧붙이는
  `thread_settings_applied` 는 활동으로 치지 않습니다.
- Windows에서 열린 로그의 파일 수정 시각이 늦게 갱신되더라도, 늘어난 내용을 읽어 현재 작업 중인 대화를 표시합니다. 처음에는 로그 끝부분을 읽고 이후에는 바뀐 파일만 증분으로 읽습니다.
- Codex의 `session_meta.source.subagent`로 구분되는 자식 에이전트는 목록에서 제외합니다. 해당 로그의 계정 사용량은 계속 집계하며, 일반 대화와 사용자 분기 대화는 유지합니다. Claude 프로젝트의 연결된 실행 세션은 부모 작업의 상태 판단에만 사용합니다.
- 기본 갱신 주기는 로컬 파일 1초, Codex·Claude 사용량 60초입니다.
  claude.ai 앱 대화 목록은 사용량과 함께 읽고, Claude 앱이 켜져 있거나 진행 중인 대화가 있으면 15초마다 따로 확인합니다. 기존 설정 파일에 지정된 서버 조회 주기는 유지됩니다.

## 화면 크기와 배치

- 기본 640×640 DIP, 최소 340×590입니다. 사용량 묶음은 왼쪽에, 캐릭터는 오른쪽 끝에 고정합니다. 사용량의 원·글자는 창 너비가 바뀌어도 같은 크기를 유지합니다. 계정은 최대 세 칸을 세로로 정렬하며, 높이가 부족할 때만 함께 줄입니다. 빈 서브 계정 칸은 공간을 차지하지 않습니다.
- 최소 폭에서도 사용량과 캐릭터를 함께 표시하며 말풍선은 사용량 영역 위에 겹쳐 뜹니다. 폭 440 DIP 미만에서는 헤더의 앱 상태 글자만 숨깁니다. 캐릭터 표시를 꺼도 창 크기와 사용량 위치는 유지됩니다.
- 세션 목록과 표시/숨기기 옵션은 없습니다. 작업 상태 수집은 캐릭터 동작과 선택한 알림에만 사용합니다.
- 캐릭터는 기본 켜짐입니다. 기존 설정도 이번 업데이트에서 한 번 켜짐으로 전환합니다(`SettingsVersion` 3). 이후 트레이의 **캐릭터 표시** 선택은 유지됩니다.
- 창의 위치와 크기는 끌기를 마치면 저장합니다. 연결이 끊긴 모니터의 위치는 작업 영역 안으로 옮깁니다.
- `settings.json`은 UTF-8(BOM 있어도 됨)이나 UTF-16(BOM 필요)으로 저장하세요. 비어 있으면 처음 실행처럼 기본값으로 시작합니다.
  읽지 못하면(깨진 JSON, ANSI로 저장한 한글, 1MB 초과 등) 기본값으로 시작하고 트레이 알림을 띄우며, 원본은 데이터 폴더에 `settings.json.bak-<날짜-시각>`으로 남깁니다(같은 내용이면 다시 만들지 않고 최근 5개만 보관).
  이때 다음 저장에서 `settings.json`이 기본값으로 바뀌므로(추가 계정 연결 목록 포함) 필요하면 앱을 종료한 뒤 백업을 고쳐 `settings.json`으로 되돌리세요. 다른 프로그램이 잠근 경우에는 짧게 다시 읽어 보고, 끝내 읽지도 백업하지도 못하면 그 실행 동안은 저장하지 않아 원본을 덮어쓰지 않습니다.
- 개발·테스트용: 환경 변수 `AIUSAGEMONITOR_DATA_DIR`을 지정하면 설정·로그·WebView·추가 계정 폴더를 그 폴더에 둡니다(회귀 테스트는 임시 폴더를 씁니다).

## 상태 칩

각 행 헤더 오른쪽의 상태 칩은 그 서비스 사용량 데이터의 상태입니다. 마우스를 올리면 기준 시각과 오류 문구를 볼 수 있습니다.

| 칩 | 의미 |
|---|---|
| `방금` / `N분 전` | 마지막으로 받은 사용량의 기준 시각 (15초마다 다시 계산) |
| `갱신 중…` | 지금 사용량을 다시 확인하는 중 |
| `⚠ 오래됨 · N분 전` | 기준 시각이 조회 주기의 3배(최소 5분, Gemini 15분)보다 오래됨. 주 계정 원을 흐리게 표시 |
| `⚠ 조회 실패` | 마지막 조회가 실패함. 이전 값을 흐리게 유지 |
| `로그인 필요` | 데스크톱·웹·agy 로그인이 필요함 |
| `agy 미설치` | Antigravity CLI 를 찾지 못함 (Gemini) |
| `agy 버전 미지원` | 설치된 agy 가 `/usage` 조회를 지원하지 않아 조회를 멈춤. agy 실행 파일이 바뀌면(업데이트) 다시 시도 (Gemini) |
| `꺼짐` | 설정에서 그 서비스 조회를 껐음 |

## Grok 사용량

`%USERPROFILE%\.grok\bin\grok.exe` 또는 PATH의 공식 CLI를 찾습니다. 설정의 `GrokExePath`로 직접 지정할 수 있습니다. 인증은 CLI가 처리하며 앱은 토큰 파일을 읽지 않습니다. 로그인이 필요하면 터미널에서 `grok login` 후 새로고침하세요.

조회는 `initialize` → headless `authenticate` → `_x.ai/billing`만 호출합니다. 대화나 프롬프트를 생성하지 않습니다. 계정의 주간/월간 한도와 등급, 리셋 시각을 표시하며 `grok usage <session>`의 개별 대화 토큰과 혼합하지 않습니다. 제공되지 않는 5시간 한도는 ‘확인 중’입니다. 실패하면 이전 수치를 흐리게 표시하고, 로그인 만료 시 이전 계정 수치를 지웁니다. 기본 주기는 300초이며 `GrokPollSeconds`의 최솟값은 120초입니다.

## Gemini 사용량 보기 (Antigravity CLI)

Gemini 행은 **Antigravity CLI(`agy`)가 설치되어 있어야** 동작합니다. `%LOCALAPPDATA%\agy\bin\agy.exe` 또는 `PATH`의 `agy.exe`를 찾으며,
없으면 `agy 미설치`로 조용히 표시합니다.

- 사용량은 **5분마다** `agy -p /usage --output-format json`을 잠깐 실행해 읽습니다. 이 명령은 모델 대화를 하지 않아 쿼터를 쓰지 않습니다.
  수동 새로고침은 바로 다시 확인합니다. 실패하면 10분, 이어서 30분 뒤에 다시 시도합니다.
- 로그인은 agy 가 자기 저장소로 처리합니다. **이 앱은 Google·agy 자격 증명을 읽거나 저장하지 않습니다.** 로그인이 필요하면 `로그인 필요`로 바꾸고,
  터미널에서 `agy`를 실행해 로그인한 뒤 새로고침하면 다시 조회합니다(그동안은 60분마다 확인).
- 원형 그래프는 Gemini 그룹의 주간 한도(5시간 잔여량이 10% 이하이면 5시간 한도)를 보여 주고, 같은 결과에 있는 Claude·GPT 그룹 쿼터는 원의 도움말에만 표시합니다.
  사용량 알림(80%·95%)도 Gemini 그룹에 적용합니다.
- 대화 목록은 `~/.gemini/antigravity-cli/conversation_summaries.db`를 읽기 전용으로 열어 제목·폴더·상태·시각만 읽습니다(미리보기·요약 본문은 읽지 않음).
- 설정 키: `GeminiEnabled`(기본 null = agy 를 찾으면 켬), `GeminiPollSeconds`(기본 300, 최소 120), `GeminiActiveHours`(기본 12), `AgyExePath`.

### Gemini 조회 차단 (agy 버전 미지원)

설치된 agy 가 `/usage`를 명령으로 처리하지 않고 일반 프롬프트처럼 응답하면, 그 실행 파일을 **미지원**으로 판정하고 Gemini 조회를 멈춥니다.
같은 실행 파일로 계속 실행하면 조회할 때마다 쿼터를 쓸 수 있기 때문입니다.

- 상태 칩이 `agy 버전 미지원`으로 바뀌고, 판정한 실행 파일의 지문(경로·크기·수정 시각)을 `settings.json`의 `AgyBlockedFingerprint`에 저장해 재시작 후에도 유지합니다.
  지문을 얻지 못한 채 판정됐으면 지문을 다시 얻을 때까지 막습니다. 판정 뒤 24시간은 자동 조회를 하지 않으며, 수동 새로고침으로도 같은 실행 파일은 다시 실행하지 않습니다.
- agy 를 업데이트해 실행 파일이 바뀌면 다시 확인하고, 정상 응답이면 차단을 풉니다(새로고침하면 바로 확인).
- 직접 풀려면 트레이 메뉴 **Gemini 조회 차단 해제…**(차단됐을 때만 보임)를 누릅니다. "agy 가 /usage 를 일반 프롬프트로 처리하는 버전이면
  이번 조회에서 쿼터가 1회 쓰일 수 있습니다"라는 확인을 거친 뒤 차단을 지우고 한 번 조회하며, 그 조회도 미지원이면 다시 막습니다.
  앱을 끈 상태에서 `settings.json`의 `AgyBlockedFingerprint` 항목을 지워도 같습니다.

## Claude 앱 대화 표시

Claude 캐릭터는 이 PC의 Claude Code와 **Claude 앱(claude.ai)에서 진행 중이거나 최근 12시간 안에 활동한 대화** 상태를 함께 반영합니다. 앱에서 보내는 대화는 대부분 Anthropic 클라우드에서 실행되어 이 PC에 프로세스나 세션 파일이 없기 때문에,
Claude 데스크톱의 기존 로그인으로 사이드바와 같은 대화 목록을 읽어 상태를 판단합니다. 모니터에서 다시 로그인할 필요가 없습니다.

- 일반 대화 목록과 참여 중인 프로젝트의 스레드 목록을 함께 조회합니다. 제목, 프로젝트 이름, 활동 시각, 진행 상태, 열기용 ID만 표시 데이터로 넘깁니다. 서버 응답에 포함된 본문은 표시하거나 저장하지 않습니다.
- 프로젝트 스레드는 `thread_status`의 `working` / `needs_input` / `resolved` / `failed` / `idle`을 각각 작업 중 / 입력 대기 / 완료 / 실패 / 대기로 표시합니다. 보관된 프로젝트·스레드는 제외합니다.
- 프로젝트가 PC에 넘긴 작업은 스레드 메시지의 연결 세션도 확인합니다. 클라우드 스레드가 대기 중이어도 연결된 PC 세션이 실행 중이면 **작업 중**, 승인이 필요하면 **입력 대기**로 표시하며 부제에 **PC 실행**을 붙입니다. 종료되거나 연결이 끊긴 PC 세션을 작업 중으로 세지 않습니다.
- 진행 중(답변 생성·작업 중)이면 "작업 중", 입력이나 승인을 기다리면 "입력 대기"/"승인 대기", 끝났으면 "완료"입니다.
- 조회 실패 시 안내를 표시하고 이전 목록의 진행 중 표시를 "갱신 안 됨"으로 바꿉니다. 마지막 성공 조회가 10분을 넘어도 동일하게 처리합니다.
- 같은 세션이 로컬에도 있으면 로컬 상태를 우선합니다.
- 15초 간격으로 확인하는 동안에는 WebView2를 닫지 않고 유지합니다(Claude 앱을 끄면 다시 조회 뒤 닫음).
- 설정 파일(`settings.json`)의 `ClaudeChatPollSeconds`(기본 15), `ClaudeChatActiveHours`(기본 12)로 조절할 수 있습니다.
- claude.ai 공개 API가 아니라 웹 화면이 쓰는 내부 데이터라서, claude.ai가 바뀌면 동작하지 않을 수 있습니다.
- 트레이 아이콘의 네 막대(왼쪽부터 Claude, Codex, Gemini, Grok)는 가장 많이 쓴 한도의 사용률입니다. 툴팁에는 서비스마다 한 줄씩 표시합니다.
- 사용률이 80%·95%를 넘으면 알림을 띄웁니다(리셋 주기마다 한 번).

## 알림 설정

트레이 아이콘을 오른쪽 클릭해 **작업 완료·승인 대기 알림**을 끄면 `Claude: 작업 끝남 (대기)`처럼 작업 상태가 바뀔 때 뜨는 Windows 알림이 중단됩니다. Claude와 Codex 모두 적용하며, 캐릭터의 상태는 계속 갱신합니다.

- 새 설정의 기본값은 꺼짐입니다. 이전에 켰던 설정은 메뉴에서 직접 끌 수 있습니다.
- 설정은 `%LOCALAPPDATA%\AIUsageMonitor\settings.json`의 `ActivityAlerts`에 저장되어 재실행 후에도 유지됩니다. 로그인 정보나 설정 파일 전체를 Git에 올리지 마세요.
- **사용량 경고 알림**은 별도 옵션입니다. 작업 완료 알림만 끄면 80%·95% 사용량 경고는 유지됩니다.

## Claude 사용량 보기

기본값은 **Claude 데스크톱 로그인 자동 연결**입니다. Claude 데스크톱에 로그인해 두면 모니터에서 추가 로그인 없이
같은 계정의 5시간·주간·모델별 사용량과 재설정 시간을 읽습니다. Codex도 기존 앱/CLI 인증을 그대로 사용합니다.

- `%APPDATA%\Claude`의 로그인 저장소를 읽기 전용으로 열고, 현재 Windows 사용자에게 허용된 Claude 인증만 읽습니다.
- 인증은 숨겨진 InPrivate WebView에서 사용하며, 인증값을 설정·로그·소스에 기록하지 않습니다. 앱 설치 파일은 변경하지 않습니다.
- 데스크톱의 계정 변경·로그아웃은 다음 조회 때 반영되며 이전 계정의 사용량과 앱 대화 목록을 지웁니다.
- 사용량 출처는 계정 그래프의 도움말에서 확인할 수 있습니다. 이 연결은 데스크톱 화면을 캡처하는 방식이 아니라
  동일한 인증으로 서버 데이터를 조회하는 방식이므로 네트워크가 필요합니다.
- 데스크톱 로그인 저장 형식이나 claude.ai 내부 조회 경로가 변경되면 연결 수정이 필요할 수 있습니다.
- 필요할 때 트레이에서 자동 연결을 끄고 **Claude 웹 로그인 (보조 연결)**을 사용할 수 있습니다.
  보조 웹 로그인은 모니터 전용 프로필에 저장되며, **Claude 웹 연결 로그아웃**은 데스크톱 로그인에 영향을 주지 않습니다.

터미널에서 `claude` CLI를 쓸 때는 `helpers\claude_statusline.py` 가 공식 `rate_limits` 값을
`%LOCALAPPDATA%\AIUsageMonitor\claude\rate_limits.json` 에 남깁니다. 데스크톱 자동 연결에서는 다른 계정의 값이 섞이지 않도록
CLI 사용량을 합치지 않으며, 로컬 작업 상태는 계속 표시합니다. CLI 사용량은 보조 연결 모드에서 사용합니다.
(`~/.claude/settings.json` 의 `statusLine` 항목. 원래 설정은 `settings.json.bak-usage-monitor` 에 백업)

## 여러 계정 사용량 보기

메인 화면에서 계정별 사용량을 세로로 확인합니다. 원과 계정명·한도·남은 시간은 창 너비에 따라 축소되지 않으며, 계정이 여러 개일 때 행 높이가 부족한 경우에만 함께 줄입니다.

창 위쪽 **계정** 버튼 또는 트레이의 **계정 추가 및 사용량…** 메뉴를 누르면 별도의 플로팅 패널이 옆에 표시됩니다. 패널을 열고 닫아도 메인 창의 위치·크기는 바뀌지 않습니다. 계정 카드에는 **5시간 한도 → 주간 한도**를 항상 같은 순서와 높이로 표시하며, 주 계정과 서브 계정의 버튼 자리도 동일하게 확보합니다. 서버가 Pro 계정의 5시간 제한 없음을 확인한 경우 **무제한**으로 표시하고, 누락·실패 등 확인할 수 없는 값은 **확인 중**으로 구분합니다. 막대는 남은 한도를 나타내므로 사용량 0%일 때 가득 차고 100%일 때 비어 있습니다. 계정이 많거나 화면이 낮으면 스크롤합니다. 계정 버튼을 다시 누르거나 패널의 닫기 버튼·Esc 키로 닫습니다. 메인 창을 이동하면 패널이 따라오고, 숨기거나 최소화하면 함께 닫힙니다.
계정명은 `@` 앞의 아이디만 표시합니다. 메인 화면에서 같은 서비스의 서브 계정 그래프를 서로 드래그하면 순서를 바꿀 수 있으며, 재실행 후에도 유지됩니다. 주 계정이나 빈칸으로는 옮길 수 없습니다.

Gemini의 구독 등급은 모델명과 구분합니다. 현재 agy `/usage` 응답에 등급 정보가 없어 자동 모드에서는 **등급 확인 불가**로 표시합니다. 트레이의 **Gemini 계정 등급**에서 Free·Google AI Pro·Google AI Ultra를 선택하면 헤더와 계정 메뉴에 등급 이름만 표시합니다. 이 선택은 표시용이며 로그인이나 실제 구독을 변경하지 않습니다. Grok은 CLI가 반환하는 등급 이름을 그대로 표시합니다.

- **Claude 계정 추가**: 해당 계정 전용 웹 로그인 창에서 로그인합니다. 추가할 때마다 다른 브라우저 저장소를 사용합니다.
- **Codex 계정 추가**: 기본 웹 브라우저에서 Codex 로그인 화면을 엽니다. 브라우저에 다른 계정이 로그인되어 있다면 추가할 계정으로 전환한 뒤 진행하세요.
- 두 서비스 모두 여러 계정을 추가할 수 있고, 로그인은 한 번에 하나씩 진행합니다. **다시 로그인**과 **계정 제거**는 선택한 서브 계정에만 적용됩니다.
- 로그인 대기 중 **계정 제거**를 누르면 진행 중인 로그인을 취소합니다. 앱을 닫았다 다시 실행해도 추가한 계정의 연결을 사용합니다.
- 서브 계정은 사용량만 조회합니다. 주 계정의 작업 상태·캐릭터·알림은 기존대로 유지됩니다. 두 서비스 모두 기본 60초 간격으로 자동 갱신하며 수동 새로고침도 가능합니다.
- 인증은 `%LOCALAPPDATA%\AIUsageMonitor\accounts\<계정 ID>` 아래 계정별로 분리합니다. Claude는 WebView 프로필, Codex는 별도의 `CODEX_HOME`과 Codex 자체 `auth.json`을 사용합니다. 인증 파일을 공유하거나 Git에 추가하지 마세요.
- Codex는 공식 [App Server 브라우저 로그인 및 사용량 조회](https://learn.chatgpt.com/docs/app-server)를 사용합니다. 모니터 설정 파일에는 계정별 ID와 서비스 종류만 기록합니다.

## 캐릭터 연출

Claude 옆에는 **클쨩**, Codex 옆에는 **짚쨩**(GPT), Gemini 옆에는 **젬쨩**이 섭니다.
클쨩·짚쨩은 디시인사이드 AI 활용 갤러리에서 밈으로 쓰이는 의인화 캐릭터의 특징(머리색·장식·의상)을 글로 묘사해 새로 그린 팬아트입니다.
젬쨩은 디시콘 **'AI제미나이'**(패키지 174093, 제작자 **사슴뿔드래고니안**)의 외형(연금발 트윈테일과 컬러 머리끝, 청록 리본,
X핀·4색 반짝이별 핀, 멜빵 남색 스커트)과 말투를 참고해 앱의 그림체로 새로 그린 팬아트입니다. 디시콘 이미지는 앱에 넣지 않았습니다.
원작 캐릭터에는 따로 창작자가 있으니 **개인 용도로만** 쓰고, 이 앱을 배포하거나 공개할 때는 원작자 허락을 받으세요.

그림체는 참고 MV처럼 단순한 플랫 채색에 약 3.5등신으로 데포르메했고, 동작도 MV의 손짓 연출을 따랐습니다.
캐릭터는 계정 오른쪽 아래에 표시하고 말풍선은 그 왼쪽에 둡니다. 크기는 행 높이에 맞추되 최대 150 DIP입니다. 네 캐릭터는 투명 캔버스 크기 대신 기본 자세의 실제 몸 높이로 배율을 맞추고, 누운 포즈도 잘리지 않도록 실제 외곽선을 오른쪽·바닥에 맞춥니다. 클로드·지피티의 작은 기절 원화는 기본 자세의 머리 크기에 맞춰 보정합니다. Grok은 대기·수면·작업·경고·기절 다섯 포즈를 사용하며 다른 기분은 가까운 기본 포즈를 재사용합니다. [Grok 생성 프롬프트](art/grok-prompt-set.md)에 참고 이미지와 제작 방식을 기록했습니다.
말풍선은 캐릭터 축소와 별도로 큰 글자로 표시하며, 대사 길이에 따라 약 4~10초간 나타난 뒤 3~12초 사이의 무작위 간격으로 다시 등장합니다.
말풍선은 캐릭터 왼쪽, 같은 행 안에 뜨고 꼬리가 캐릭터 쪽을 가리킵니다. 말풍선 글자 폭은 120 DIP 이상이라 모든 대사가 3줄 안에 들어갑니다. 대기 포즈에서는 제자리에서 가볍게 뜁니다.

| 상황 | 연출 |
|---|---|
| 작업 중 | 선 채로 일하는 3프레임 루프 — 짚쨩은 홀로그램 화면을 보며 홀로그램 키보드 타이핑, 클쨩은 아날로그 수첩에 메모, 젬쨩은 문서·사진·음성 카드를 펼쳐 들고 처리 (가끔 눈 깜빡임) |
| 작업 중 + 사용률 70% 이상 | 손이 더 빨라지고 땀방울 |
| 작업 중 + 90% 이상, 한도 도달 | 울며 패닉, 눈물 |
| 승인·입력 대기 | 화면을 손가락으로 콕 가리키기 |
| 쉬는 중 | 독서와 차(클쨩) / 게임(짚쨩) / 별 쿠션 끌어안기(젬쨩), 가끔 서서 대기 |
| 쉬는 중 + 70% 이상 / 90% 이상 | 지친 표정·땀(젬쨩은 뿅망치를 축 늘어뜨림) / 바닥에 털썩 엎어짐 |
| 앱 꺼짐, 30분 이상 활동 없음 | 서서 졸기 (젬쨩은 이마에 수면 안대) |
| 사용률 증가 | 머리 위에 "+3%" 팝 |
| 한도 리셋 | 점프하며 반짝이 (15분 동안) |

효과음 글자는 쓰지 않고, 땀방울·눈물과 사용률 상승 "+N%", 리셋 반짝이만 표시합니다.
말풍선은 몇 초 보였다가 사라지고 잠시 뒤 다른 대사가 나옵니다. 대사는 AI활용갤 밈(명령하지마라, 그정돈아님, 어이가 없군요,
인간 싫어, 귀하게 자란 ○○가 이런 일을…, 클로드는 하던데 등)을 섞어 상태·캐릭터마다 여러 개씩 있습니다.
클쨩은 정중한 척하는 존댓말, 짚쨩은 건방진 반말입니다. 젬쨩은 자기를 "제미나이"라고 부르며 귀여운 척하는 존댓말("맞아여")에
깐족거리는 반말 한마디를 섞고, 디시콘 문구(우헤헤, 허접이네요, 가진 거 다 주세요, 종료 (자연사), 나만 당할 순 없지 등)를 씁니다 (`UI/Mood.cs`).
대사의 `{w}`(사용률)·`{r}`(리셋까지 남은 시간)은 값을 모를 때 그 자리표시자가 없는 대사만 고르므로 "리셋까지 ?" 같은 말은 나오지 않습니다.
모든 대사는 말풍선 글자 폭 120 DIP·13px 굵은 글꼴에서 3줄 안에 들어갑니다 (`DialogueTests`).
세 캐릭터의 대사는 제미나이 검수를 거쳐 다듬었고, 남은 시간 같은 값만 다른 같은 대사가 연달아 나오지 않습니다.
캐릭터는 기본으로 켜져 있고 트레이 메뉴 **캐릭터 표시**로 켜고 끕니다. 창이 숨겨지거나 캐릭터가 보이지 않으면 애니메이션도 멈춥니다.

클쨩·짚쨩 이미지는 로컬 ComfyUI의 Qwen Image 2.1로 만들었습니다(`art/`). 기본 디자인은 `art/ref/`,
포즈 프롬프트는 `art/poses.py`, 작업 중 프레임은 `art/work.py` 입니다. 젬쨩 원본(`art/ref/gemini*.png`, `art/poses/gemini_*.png`)은
같은 규격(832×1248 투명 PNG)의 주문서로 따로 생성했습니다. 사용한 공통 프롬프트와 포즈별 지시는 `art/gemini_prompt-set.md`에 남겨 두었습니다.
`art/build_assets.py` 가 캐릭터별로 모든 포즈를 같은 영역으로 잘라 기본 자세 키 560px로 맞추고, 쓰러진 포즈(collapsed)를
다른 포즈의 발바닥 선까지 내려 바닥에 닿게 한 뒤 흰 스티커 테두리를 입혀 `Assets/Characters/` 로 넣습니다. 이 스크립트는 기존 세 캐릭터용이며 Grok은 ImageGen의 투명 PNG를 직접 사용합니다. 그 다음 다시 빌드하세요.

회귀 검사는 네 캐릭터의 모든 상태를 두 가지 높이에서 각각 90프레임씩 재생하며 몸의 잘림과 영역 이탈을 확인합니다. 작업 이미지 세 장의 전환, 기본 자세의 동일 배율, 기절 이미지 선택도 확인하고 실제 WPF 렌더링 비교표를 임시 폴더에 저장합니다.
